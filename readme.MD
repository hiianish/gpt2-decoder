# Mini-GPT: Training & Inference Optimization

A small GPT-style transformer, trained from scratch and pushed through six
real optimization techniques — each one benchmarked, not just claimed.

**Course:** Deep Learning (ES532) · Dr. Yashwant Singh Patel
**Compute:** Google Colab, free T4 GPU
**Model:** ~30M param decoder-only transformer · **Data:** ~100MB OpenWebText slice, GPT-2 BPE

## The idea

Build the model once, then apply five *free* optimizations (same output,
faster/leaner) and one *real* tradeoff (quantization), measuring each one
instead of assuming it works.

## Phases

| # | Phase | Notebook | What it proves |
|---|---|---|---|
| 1–3 | Baseline → Mixed Precision → Memory Engineering |  AMP + gradient checkpointing/accumulation cut time & memory, loss unchanged |
| 4 | Custom Fused Attention Kernel | Hand-written Triton kernel beats PyTorch's SDPA on forward-pass latency |
| 5 | KV-Cache Generation |  Cached generation is mathematically identical, and gets *faster relative to naive* as output length grows |
| 6 | INT8 Quantization | The one deliberate tradeoff: smaller/faster on CPU, small measured perplexity cost |
| — | Final Benchmark Report |  Pulls every phase's results into one figure + `FINAL_REPORT.md` |
| — | Hugging Face Upload |  Publishes the trained model (`config.json`, `model.safetensors`, model card) |

## Project structure

```
model/
  gpt.py          MiniGPT transformer (GPTConfig, Block, generate/generate_with_cache)
  attention.py    CausalSelfAttention (vanilla) + FusedCausalSelfAttention (Triton) + KVCache
data/
  prepare_data.py Streams OpenWebText subset, tokenizes with tiktoken, saves train.bin/val.bin
config.py         Architecture config + phase toggle flags (use_amp, use_grad_checkpointing, ...)
train.py          Training loop for Phases 1-3, logs every run to results/logs.csv
generate.py       KV-cache correctness check + generation speed benchmark (Phase 5)
quantize.py       FP32 vs INT8 comparison (Phase 6)
benchmark.py      Unified report across all logged results
upload_to_hf.py   Packages + pushes the trained model to the Hugging Face Hub
```

## Running it

Each notebook is self-contained — it writes out the current project files via
`%%writefile`, mounts Google Drive to persist data/checkpoints/results across
sessions, and picks up wherever the previous notebook left off. Run them in
order (1→6, then the report, then the HF upload), backing up `checkpoints/`,
`data/`, and `results/` to Drive at the end of each one.

## Results

See `results/FINAL_REPORT.md` (generated by the benchmark notebook) for the
actual measured numbers. Four of five speed/memory optimizations are free;
only INT8 quantization trades a small, explicit amount of accuracy for
CPU-deployment gains — that asymmetry is the project's core finding.
